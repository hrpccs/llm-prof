# 持续 profiling 全链路理论框架：采集 → 处理 → 传输 → 存储

> 关联：`docs/stack-compression-proposal.md`（栈压缩专项）、`docs/stack-compression-review.md`（专家审查）
> 本框架把"栈压缩"放进全链路语境：每阶段给出**开销/带宽的理论模型**、**实测参数**、
> **优化原则**与**论证方法**。所有实测数字来自本仓库可复现实验。

---

## 1. 链路分解（llm-prof 实际路径）

```
┌─ 采集（内核侧）─────────────────────────┐
│ perf_event 中断 → eBPF native unwind    │  开销：中断进出 + eBPF 执行（∝ 栈深）
│   → python unwind（混合栈）→ frame_data │  带宽：每样本 send_size（可变）
└───────────────┬─────────────────────────┘
                │ bpf_ringbuf（有损通道，满则丢）
┌─ 传输 ────────▼─────────────────────────┐
│ ringbuf 内存拷贝 → 用户态轮询读取        │  带宽：rate × N_cpu × E[send_size]
└───────────────┬─────────────────────────┘
                │ loadBpfTrace 解码
┌─ 处理（用户态）─────────────────────────┐
│ 解码 → 符号化（native ELF / python TLS）│  开销：∝ 样本数 × 栈长；符号化有缓存
│ → 聚合（LocalReporter 计数 map）         │  延迟：ProcessedUntil latency
└───────────────┬─────────────────────────┘
                │ pprof protobuf（gzip.BestSpeed）/ txt / svg
┌─ 存储 ────────▼─────────────────────────┐
│ 文件 / 网络 → Parca/Pyroscope 存储       │  存储量 = 窗口 × 带宽（或聚合后 × distinct）
└──────────────────────────────────────────┘
```

代码位置：ringbuf 分配 `tracer/tracer.go:628`、每样本发送 `tracemgmt.h:578`、丢事件 `tracemgmt.h:588`、
解码 `events.go:229`、聚合 `reporter/local.go:77-117`、pprof 输出 `internal/pprofout/pprofout.go:248`。

## 2. 理论建模

### 2.1 采集阶段：开销模型

**单样本成本分解**（实测参数来自 rate_curve / stack_exp 实验）：

```
T_sample = T_intr + T_ebpf(stack)
         = T_intr + Σ_{帧 i} (c_unwind + c_lookup)          # native 帧
                   + Σ_{python 帧} c_python                  # python 帧（TLS 读取+解码）
```

实测标定（10000Hz，case_hotspot，栈深 36，总开销 +1.9% ≈ 0.57s/30s）：
- 中断进出 `T_intr ≈ 2µs`/样本（**固定成本，与负载无关**——占 10000Hz 开销的大头）
- unwind `c_unwind ≈ 0.3µs`/帧（含 delta 二分查找，栈深 36 → ~11µs/样本）
- 总开销 = rate × (T_intr + E[栈成本]) —— **与采样率线性，与栈深线性**

**理论结论**：采集开销的可优化面 = ① 固定部分 T_intr（中断进出，受硬件/内核限制，接近下限）；
② 每帧成本（unwind 指令数、查找算法）；③ **采样率本身**（见 2.5 精度权衡）。

### 2.2 传输阶段：带宽模型与信息论下界

**现状带宽**：

```
B = rate × N_cpu × E[send_size]
```

两个口径（review 已指出）：ringbuf 预算 = rate × N_cpu × `Sizeof_Trace`(25.3KB，静态分配，10000Hz×16 核撞 2GB cap)；
实际生产 = rate × N_cpu × `send_size`（动态，帧数×8B + 头）。

**信息论下界**（无损，逐样本独立）：
```
B_min = rate × N_cpu × H(栈) × (每符号编码位数)        # H = 栈分布的熵
```
**时间差分下界**（相邻样本相关时）：
```
B_min' = rate × N_cpu × H(栈_t | 栈_{t-1})            # 转移熵 ≤ H(栈)
```
**字典化工程模型**（首次传输摊销）：
```
B_dict = rate × N_cpu × S_id + D_window × S_full / T_window
       ≈ O(rate × 8B) + O(变化率 × 全栈)              # 稳态：带宽 ∝ distinct 变化率
```
**关键判据**（差分 vs 纯字典的取舍）：每窗口变化条目 × 条目字节 < 每窗口样本数 × ID 字节 → 差分胜出。
**零收益拐点**（字典摊销吃掉全部收益）：D × S_full ≈ N × S_id 时（review 实测 d200 场景
28K-35K distinct × 200 帧 ≈ 45-57MB vs 原始 ~58MB → 逼近拐点）。

### 2.3 处理阶段：解码与符号化成本

```
C_process = N × (C_decode + C_symbolize(栈) + C_aggregate)
          = N × C_decode + N × E[栈长] × c_sym + N × c_agg
```
- 符号化缓存（native.go syms 进程级缓存）：同地址二次命中 O(1)，**摊销后 c_sym 远小于首解**；
- **先聚合后导出**（LocalReporter 计数 map，Parca 同模式）：把下游处理量从 O(N) 降为 O(D)——
  这是处理阶段最重要的优化原则（见 §3.2）；
- 处理延迟（ProcessedUntil）受 ringbuf 消费速率约束；消费跟不上 → 背压 → 丢事件。

### 2.4 存储阶段：模型

```
存储量 = Σ_窗口 (聚合后 distinct 栈 × 栈字节)          # 若先聚合
       ≈ D_total × (E[栈长] × 8 + 符号表摊销)
```
pprof protobuf 本身做字符串表 + varint（单 profile 内去重）；gzip/zstd 进一步压符号名。
**存储侧与传输侧正交**：传输侧省的是"重复样本的字节"，存储侧省的是"唯一栈的表示"——两者可叠加。

### 2.5 采样率的统计语义（贯穿全链路的杠杆）

profiling 是**无偏估计器**：n 个样本下计数 p̂ 的相对误差 ~ 1/√n（CLT）。
- 精度需求给定 → 最低采样率 n_min → 开销/带宽下界随之确定；
- **采样率自适应优化问题**：min 开销  s.t. 估计误差 ≤ ε —— 求解最优 rate；
- 内核 `perf_event_max_sample_rate` 是"上限保护"而非"精度自适应"——理论上有更优策略
  （按负载/栈动态调 rate，低活跃期降采样，信息损失可量化）。

## 3. 优化原则（理论指导，按优先级）

### P1 尽早去重（在源头消除冗余）
- 理论依据：冗余度在源头最大（同一栈反复出现，155:1），越早消除，下游全链路受益；
- 实现：内核侧栈字典（ID 化传输）——把 B 从 O(rate) 降为 O(变化率)；
- 边界：字典摊销拐点（§2.2），高基数负载需配合时间差分与分层 ID。

### P2 尽早聚合（在源头合并计算）
- 理论依据：处理成本 C = N × c，聚合后 = D × c + N × c_agg（D ≪ N）；
- 现状：llm-prof 已在用户态聚合（LocalReporter）✓；**可进一步下推**：eBPF 侧 per-CPU 计数
  （栈 ID → count），用户态只收聚合结果——Parca 内核侧同款；代价是丢失样本级细节
  （时间分布、per-trace 关联），需按场景权衡。

### P3 延迟-带宽权衡（批量传输）
- 批量 = 更少的事件/包、更高压缩率（窗口内去重），代价是延迟与内存；
- 理论模型：延迟 ≤ 批窗口 + 处理；带宽 = f(批大小) 单调减；
- 现状：llm-prof 批处理 maxEvents=4096（`events.go:38`）已部分批量；窗口差分（5s）是进一步的批量化。

### P4 采样率-精度权衡（1/√n 法则）
- 自适应采样率：低活跃期降采样、热点期升采样，误差预算分配；
- 与压缩正交：压缩解决"传多少"，自适应解决"采多少"——两者收益相乘。

### P5 缓存摊销（符号化/解码）
- 符号化缓存（进程级 syms）、TLS 基址缓存、delta 缓存（已实现 native 侧）；
- 理论：缓存命中率 → 摊销成本；LRU 容量 = f(活跃栈数)。

## 4. 论证方法（模型如何验证）

| 模型 | 预测 | 验证手段（已有方法论） |
|---|---|---|
| T_sample = T_intr + Σc_frame | 开销 ∝ rate、∝ 栈深 | `run_stack_exp.sh` 三段法（中断/过滤 vs unwind vs unwind+字典）；rate_curve 多档采样率曲线 |
| B = rate × N × E[send_size] | 带宽线性涨；压缩后趋平 | 内核 per-CPU 字节计数器（M1）+ 用户态 `len(RawSample)` 双口径；"采样率-带宽解耦曲线"是 claim 3 核心证据 |
| B_min = N × H(栈) | 压缩率接近熵下界 | M0 离线模拟器：熵/转移熵 vs 实测字节率（Miller-Madow 校正、报告样本量/支撑集比） |
| 字典拐点：D × S_full ≈ N × S_id | 高基数负载收益归零 | 字典容量扫描（1K/4K/16K/64K）miss/evict 曲线；d200 负载实测 |
| 1/√n 精度法则 | 估计误差随 rate 平滑下降 | 同负载多采样率（100/1000/10000Hz）计数分布对比（KS 检验） |
| 聚合收益：O(N)→O(D) | 用户态处理量大幅下降 | ProcessedUntil P50/P99（改为默认输出）、CPU 时间对比 |

统计协议：每配置 ≥5 轮、A/B 交替轮序、median+IQR、配对 bootstrap（review M2）。

## 5. 现状 vs 理论最优差距表

| 环节 | 现状（实测/代码） | 理论最优 | 差距来源 |
|---|---|---|---|
| 采集 | T_intr ≈ 2µs/样本 + 0.3µs/帧 | 中断进出 ~硬件下限；unwind 可再优化（delta 缓存命中率 0%，见 review） | 中断固定成本不可消除；unwind 指令仍有冗余 |
| 传输 | 每样本传完整栈（155:1 冗余）；ringbuf 静态 25.3KB×rate×CPU | 每样本 32 位 ID + 窗口 delta（≈0.01× 现状） | 未做字典化/差分（提案 M1-M2） |
| 处理 | 用户态解码+符号化+聚合（聚合已做） | eBPF 侧 per-CPU 聚合（只收 D 个计数） | 聚合未下推（P2 边界：需保留样本级细节的场景） |
| 存储 | pprof gzip（单 profile 去重） | 跨 profile 字典（栈表复用）+ 分层存储 | 存储侧字典化未做（与传输侧可叠加） |

## 6. 一个统一视角：整条链路是一棵"冗余消除"流水线

```
采样流（N 个样本，熵 H）→ 去重（D 个栈）→ 差分（Δ 个变化）→ 聚合（D 个计数）→ 符号化（D 个符号串）
   N          H(栈)      H(栈_t|栈_{t-1})      D × 8B           符号表
   每阶段削减量可独立量化，消融 = 逐段打开/关闭，总收益 = 各段乘积（近似）
```

论文级论证的完整叙事 = 每阶段的模型 + 实测参数 + 消融收益分解 + 与下界的差距。
`stack-compression` 提案是"去重/差分"段的实现；本框架给出其余各段的理论位置，
使整个工作从"一个压缩技巧"升级为"一条链路的最优冗余消除"。
