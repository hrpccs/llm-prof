# Workload 感知压缩：画像特征 → 压缩机制映射

> 关联：`stack-compression-proposal.md`（压缩方案）、`profiling-pipeline-theory.md`（全链路模型）
> 核心论点：**压缩参数不该是静态常量，而应由 workload 画像驱动**。LLM 推理/训练等
> 生产 workload 有强结构规律（周期性、阶段化、热点集中），画像先行即可为压缩
> 提供收敛速度、窗口大小、JIT 处理策略等关键参数。

---

## 1. 实测画像：两种 workload 的对比（1000Hz，12s，llm-prof）

| 画像特征 | case_hotspot（单热点循环） | train_torch（LLM 风格训练循环） |
|---|---|---|
| 样本 / distinct 栈 | 5163 / 33 | 2291 / 366 |
| 冗余比 | **155:1** | **6.3:1** |
| top1 栈占比 | ~90%（bottleneck） | 19.2% |
| top5 / top20 占比 | ~99% / ~100% | 58.6% / **80.1%** |
| 平均栈长 | 14 | 12 |
| 无符号（JIT/匿名）帧 | ~0% | **20.0%** |

**解读**：
1. **train_torch 仍是 Zipf 但更平坦**：top20 覆盖 80% 样本 → 字典化后 **80% 样本命中 20 个栈**，
   字典收益依然显著（稳态 80% 样本只传 ID）；
2. **6.3:1 冗余是"窗口内聚合"口径**——训练循环是周期性的，相邻 iteration 栈序列几乎相同，
   **时间差分（转移熵）收益会远高于静态冗余比**（静态画像看不到，需 M0 时间序列）；
3. **JIT 帧 20%** 是压缩的**关键挑战**：torch inductor/算子 JIT 代码地址随机（ASLR + 代码缓存）
   → 地址级指纹 miss → 需要 **build_id + offset 归一化**（内核 `stackmap.c` 已有该路径）。

## 2. LLM workload 的结构规律（压缩可利用的先验）

### 2.1 训练（train_torch 已验证的形态）
```
循环 = load_batch(IO 等待) → forward → backward → optimizer.step()
```
- **严格周期性**：每个 iteration 的栈序列几乎相同 → distinct 栈**快速收敛**
  （前几个 iteration 后不再新增）→ 字典预热成本一次付清；
- **多阶段交替**：IO 等待 / 计算 / 同步点 三类栈交替 → 窗口内平稳、窗口间有模式；
- **确定性算子集**：GEMM/attention/norm/optimizer 的 native 帧稳定 → 符号化缓存命中率高。

### 2.2 推理（vLLM 类，待实测）
- **prefill vs decode 两阶段**：栈形态显著不同（batch 计算 vs 逐 token 调度）→ 阶段检测
  可驱动窗口自适应；
- **固定线程池**：调度线程 / 算子线程 / 通信线程各自栈模式稳定 → 线程级（per-TID）字典
  命中率更高；
- **GPU 等待主导**：同步点/通信等待的 off-cpu 栈几乎不变 → 时间差分收益最大场景
  （对应 pipeline-theory §2.2 的转移熵下界）。

### 2.3 共同点
- **热点集中**：top20 栈覆盖 80%+ 样本（实测）→ 小容量字典（如 64-256 项）即可覆盖稳态；
- **长尾存在**：20% 样本分布在 ~300+ 个栈 → 长尾需要 LRU 兜底 + 差分覆盖。

## 3. 画像如何驱动压缩（机制映射）

| 画像特征 | 测量（M0） | 驱动的压缩参数/机制 |
|---|---|---|
| **distinct 收敛曲线**（新增栈数 vs 运行时间） | 时间序列导出 | 字典容量（收敛点 → 容量下限）；**预热窗口**（何时进入稳态） |
| **转移熵 / 加权 Jaccard**（相邻窗口） | 时间序列导出 | **差分 vs 纯字典的选择**；窗口大小（平稳期大窗口、突变期小窗口） |
| **阶段检测**（栈分布突变点） | 窗口分布距离（如 JS 散度） | **窗口自适应**：阶段切换时重置差分基线 |
| **JIT 帧比例** | 无符号帧占比 | **build_id+offset 归一化**开关（JIT > 阈值时启用） |
| **top-K 覆盖率** | 分布 | 字典容量下限；**热点专用快速路径**（top 栈免哈希？） |
| **栈长分布** | 帧数分布 | 每样本字节预算模型（pipeline-theory §2.2 的 S_full） |
| **符号化缓存命中率** | 同地址重复率 | 用户态缓存容量（P5） |

**workload 感知压缩 = 画像特征 → 参数查找表**（或在线自适应）：
```
训练循环 → 大窗口差分 + 小字典 + JIT 归一化
推理(prefill/decode) → 阶段自适应窗口 + per-TID 字典
单热点服务 → 小字典即可（155:1 冗余）
深栈/高基数 → 关闭字典，纯差分（review 的零收益拐点）
```

## 4. 论证价值（为什么这能成为论文贡献）

1. **画像本身是贡献**：首次给出 LLM 训练/推理 workload 的**栈级数据画像**
   （distinct 收敛、转移熵、JIT 比例、阶段结构）——测量论文的素材；
2. **workload 感知压缩是"自适应系统"**：不是单一压缩算法，而是
   **特征 → 参数映射 + 在线检测器**——系统论文的叙事（motivation → 设计 → 评估）；
3. **与全链路框架衔接**：画像特征同时喂给 P1（去重）、P3（批量窗口）、P4（自适应采样率）、
   P5（缓存）——一个画像，四段优化；
4. **反例也是贡献**：深栈/高基数负载的"压缩无效区"边界（review 已指出 d200 逼近拐点），
   用画像特征预测压缩收益的**适用边界**。

## 5. 实验计划（M0 画像实验的具体化）

### 5.1 负载矩阵（按规律分类）
| 负载 | 规律类型 | 画像目标 |
|---|---|---|
| case_hotspot | 单热点 | 基准：极致 Zipf |
| train_torch | 周期训练循环 | **收敛曲线 + 转移熵**（LLM 训练代表） |
| vLLM 推理（可选，.venv-vllm） | prefill/decode 阶段 | 阶段检测 + per-TID |
| case_io | 等待主导 | 差分收益上界 |
| stack_bench d200 | 深栈高基数 | 压缩无效区边界 |
| case_misleading | 双热点切换 | 阶段突变检测 |

### 5.2 测量项（每负载）
1. distinct 收敛曲线（新增 distinct/秒，首 30s）；
2. 滑动窗口（5s）转移熵与加权 Jaccard 的时间曲线；
3. 阶段检测：窗口分布 JS 散度，突变点定位；
4. JIT/无符号帧比例、栈长分布、top-K 覆盖率；
5. 输出：每负载一张画像表 + 压缩参数建议（字典容量/窗口大小/差分开关/JIT 归一化开关）。

### 5.3 验证
- 画像驱动的参数 vs 静态默认参数：**压缩率与开销的对比**（同负载、同采样率）；
- 参数迁移性：train_torch 画像出的参数用在另一训练负载上是否仍优（泛化性）。

## 6. 落地顺序

1. **M0a 样本流导出**（`loadBpfTrace` 后按 ktime 写序列）——一切画像的前提；
2. **M0b 画像脚本**（`demo-cases/analyze_compress.py`）：收敛曲线/转移熵/阶段检测/JIT 比例；
3. **M0c 画像报告**：§5.1 六负载 × §5.2 五测量项，形成"规律→参数"查找表；
4. **M1 压缩实现**：按查找表实现参数化压缩（字典容量/窗口/差分/JIT 归一化皆可配置）；
5. **M2 验证**：画像参数 vs 默认参数对比实验 + 迁移性实验。
